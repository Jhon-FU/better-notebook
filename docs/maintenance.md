# 维护说明

## 代码边界

页面结构在 `notebook.html`，样式在 `src/styles/notebook.css`。`src/js/app.js` 是无需构建的浏览器 ES 模块，现有画布、图片、历史和文件功能按注释分区；编辑同步的可复用逻辑位于 `editor-sync.js`。

后续新增功能可继续抽取小模块。新增浏览器脚本或资源时，需要同时更新 `scripts/server.ps1` 的静态资源白名单，避免将个人文件目录作为公共静态目录暴露。

根目录的 PowerShell 文件仅转发参数。实现放在 `scripts/`，应用根目录始终取该目录的父目录。这样原来的快捷方式、图标和默认笔记路径都能继续使用。

## 保存约定

1. 编辑时以可见的 `.text-content.innerHTML` 同步文本模型。
2. `input` 和 `compositionend` 负责同步并触发防抖保存。
3. 所有保存与导出统一调用 `serializeForSave()`，最后补做一次编辑同步。
4. `revision` 用于判断保存期间是否产生新修改；旧请求不能清除新修改的未保存状态。
5. `saveQueue` 串行执行普通保存，保持写入顺序。
6. 保存失败仍保留未保存状态，并显示错误或浏览器本地回退提示。

不要在保存时调用 `exitEdit()`，以免打断中文输入、光标或选区。不要仅凭保存请求成功就无条件设置 `dirty=false`。

## 操作历史约定

- `history.js` 使用撤销栈和重做栈，最多保留 40 次已完成的画布操作。
- 每次操作记录变更前状态，并在完成后比较实际变化；空操作不入栈，也不清除重做分支。
- 一次拖动、缩放或旋转在松开鼠标后才计为一步。
- 编辑文字时 Ctrl+Z、Ctrl+Y 和 Ctrl+Shift+Z 由浏览器处理。退出编辑后，整次文字编辑与块级字号／对齐修改作为一步画布操作。
- 快照保存图片资源映射，资源字符串共享；恢复时同时恢复元素和对应图片。
- 打开另一文件会清空历史，避免将前一个文件内容撤销进新文件；导入备份到当前文件则保留可撤销记录。
- 恢复纸张外观使用 `applyPaper()`；用户更换纸张使用 `setPaper()`，避免恢复历史时产生新记录。

## 测试

`tests/editor-save.test.js` 通过轻量 DOM/文件接口替身执行真实应用代码，验证编辑同步、快捷键、自动保存、导出、另存为、失败和并发状态。它不替代浏览器中的选区、输入法和排版检查。

`tests/server.test.js` 使用真实 Windows PowerShell 服务验证入口、模块与样式资源、私有路径隔离，以及临时数据目录的读写。

`tests/history.test.js` 验证首次操作、连续操作、历史边界、分支、图片资源、编辑模式快捷键，以及恢复后自动保存。

`tests/note-format.test.js` 验证版本、字段类型、元素标识、数字范围与图片引用；`tests/file-open.test.js` 验证打开失败不切换目标、不破坏历史、不改写所选文件，并包含真实临时文件的字节保留检查。

修改相关逻辑后运行 `npm run check` 和 `npm test`，再在独立测试端口完成浏览器检查。不要把真实 `notes.json` 当测试夹具。

## 文件读取约定

- `note-format.js` 是外部笔记数据的统一校验入口，格式见 [笔记文件格式](note-format.md)。
- `parseNoteText()` 同时处理 JSON 语法和结构校验。`applySavedData()` 也会先校验全部内容，再修改模型、画布和历史。
- 打开文件先等待旧保存请求完成、读取并校验，再征求替换确认。确认成功后才绑定文件句柄、清除旧定时器并标记为已加载。
- 打开或恢复文件不会自动改写它。导入备份则是对当前笔记的一次可撤销修改，后续仍保存到当前目标。
- 文件读取期间暂停新保存；打开失败或取消后恢复原文档的待保存任务。
- 默认文件只有读取校验成功或服务明确返回 404 时才允许写入。读取失败后的恢复副本需另存为，避免覆盖损坏文件。

## 已知事项

以下问题仍需独立处理：

- 浏览器本地回退副本和默认文件的版本比较、恢复提示。
- 原子写入与自动历史备份。
- 多窗口同时编辑的冲突处理、完整关闭保存保障。
- 导入富文本的安全过滤。

修改数据格式时保持 `version` 字段并提供迁移逻辑。避免把上述任务混入无关的样式或文件整理提交。
